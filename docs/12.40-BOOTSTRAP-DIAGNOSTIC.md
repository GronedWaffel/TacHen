# Historical diagnostic design

This document describes an earlier private diagnostic candidate, not the current public beta ELF.

# Private 12.40 bootstrap diagnostic, p1

This is an evidence-capture build, not a confirmed compatibility fix. It retains
the current menu and features. Do not publish it as a normal release.

## Existing evidence

The supplied runtime log reaches phase 203 (`__kernel_init`) and records 1,010
kernel reads. Both sampled reads were still in progress (`readPhase=1`), so their
`result=0` fields do not prove those particular reads completed. The ShellUI
process identity then fails with ESRCH. No menu hooks were published and neither
render nor input became active. This does not identify a fault instruction.

The empty runtime-fault.bin is expected when the standalone coordinator does not
receive one of its handled fatal signals. It does not capture ShellUI faults.

## Comparison with the successful etaHEN adaptation

The local experimental report-triage state records the private controller p6
candidate succeeding on 12.40 by tester report. The corresponding unified source
is in compatibility-worktrees/etahen-main-update/Source Code/shellui/src/prx.cpp.
It removes the long startup debugger-auth override and changes module lookup to
the SDK kernel-read path. Earlier failures had different last observed symbol
lookups; the notes explicitly do not claim a proven fault instruction.

TacHen already skips the SDK resident credential patch and uses read-only Mono
module lookup. Its reported failure is earlier, in the resident CRT kernel setup.
Do not reintroduce the old broad permission change or copy guessed offsets.

## What this build captures

Build with TACHEN_BOOTSTRAP_TRACE=1. The normal build leaves this observer disabled.
The private observer retains the existing bounded first-signal trace: it waits
for the launch thread restoration, then observes kernel initialization before
Mono can forward an original signal. Only its exact verified checkpoint trap is
accepted as completion. Unexpected signals are forwarded unchanged; a signal
racing the timeout is also preserved. There is no automatic reinjection.

The runtime log includes firmware/source identity, kernel initialization return
status, derived kernel globals, and the last 16 kernel read addresses, lengths,
completion flags and results. It never stores the data read from those kernel
addresses. The first-stop capture includes registers and instruction bytes where
readable. The logged deck load bias can be used with the retained matching deck
ELF. INT32_MIN denotes a call that has not returned, not a kernel error code.

A bounded stack snapshot may be saved separately as bootstrap-stack.bin; the log
explicitly records whether it was saved successfully. The first observed signal
can be a recoverable runtime signal, and the observer changes timing, so neither
a signal nor a successful diagnostic run alone establishes the root cause.

## Tester steps

1. Reboot and jailbreak using the same setup as the failed attempt.
2. Load TacHen-12.40-startup-diagnostic-p1.elf once using the usual ELF loader.
   Do not also load a different TacHen build during this boot.
3. Wait up to one minute, then copy /data/tachen/runtime.log via FTP before
   loading TacHen again. Report whether the menu opened or a system error appeared.
4. If the log says `bootstrap stack saved: ok=1`, also send
   /data/tachen/bootstrap-stack.bin privately. It can contain process memory;
   do not post it publicly. The ELF and ordinary log are sufficient to start
   analysis if the stack file was not saved.

No console was injected during preparation. Hardware validation is pending.
